# Борисхоф Digital Control

Дашборд digital-направления холдинга: Яндекс Метрика, Яндекс Директ подрядчиков Tandem и RTA, Calltouch, планы месяца и классифайды. Срез по брендам и линиям NC (продажи) и AFS (сервис).

EXEED и Esteo (Эксид и Эстео) — один проект «Exeed + Esteo»: кабинеты Директа, счётчики Метрики и сайты Calltouch остаются своими, а бренд, факт и планы суммируются. Если в классифайдах уже есть строка Exeed+Esteo, она и показывается, отдельные строки Exeed и Esteo к ней не прибавляются. Seres (borishof-seres.ru) из справочника убран и не запрашивается.

Метрика ходит в API одним запросом на счётчик: дата и домен входа сразу за оба периода. Ответ лежит в `data/cache`. Закрытый день хранится 12 часов, период с сегодняшним днём — 45 минут. Одновременно не больше трёх запросов. При 429 запрос повторяется дважды, затем берутся последние сохранённые цифры и в статусе пишется, какой счётчик не обновился. Повторное открытие того же периода сеть не трогает.

Без токенов экраны открываются, но цифры источников пустые: в шапке написано, какого ключа нет. Подставных демо-кампаний нет. Как устроены алерты, правила и гипотезы — в [docs/IMPROVEMENTS.md](docs/IMPROVEMENTS.md).

## Локально

Нужен Node.js 20 или новее.

```bash
npm install
npm test
npm run dev
```

Интерфейс: http://localhost:3010

Сборка: `npm run build`, затем `npm start`.

## Где держать ключи

Локально все секреты лежат в `.env.local` в папке проекта (файл в git не входит). Скопируйте туда `.env.example` и впишите значения. Рядом можно держать один файл `data/tokens.json`:

```json
{"metrika":"...","direct":{"Tandem":"...","RTA":"..."},"calltouch":{"47639":"..."}}
```

Старые `data/direct-tokens.json` и `data/calltouch-tokens.json` тоже читаются. Если в них только `{"_movedTo":"data/tokens.json"}`, берётся единый файл, а сам указатель не считается токеном и не затирается. Все эти файлы в git не входят.

При выкладке тот же набор передаётся переменными окружения или секретами площадки. Файл `.env` на сервер копировать не нужно.

Порядок, откуда берётся секрет:

1. Именная переменная окружения, если она не пустая.
2. JSON-переменная, если она есть: `YANDEX_DIRECT_TOKENS`, `CALLTOUCH_TOKENS`.
3. `data/tokens.json`: Метрика в `metrika`, Директ в `direct`, Calltouch в `calltouch` по siteId.
4. Старый файл `data/direct-tokens.json` или `data/calltouch-tokens.json`, если это не указатель `_movedTo`.
5. Поле кабинета в `data/settings.json`, если это не маска `••••`.

Так пустой файл на сервере не перекрывает секрет из окружения, а дома можно работать и без переменных, одним JSON.

## Переменные

- `YANDEX_METRIKA_OAUTH_TOKEN` — один OAuth на все счётчики
- `YANDEX_DIRECT_RTA_OAUTH_TOKEN`, `YANDEX_DIRECT_TANDEM_OAUTH_TOKEN` — токены Директа
- `YANDEX_DIRECT_TOKENS` — тот же смысл одним JSON
- `CALLTOUCH_TOKENS` — JSON `{"siteId":"токен"}`
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
- `TELEGRAM_MIN_SEVERITY=critical` — слать только критичные
- `TELEGRAM_DRY_RUN=1` — не отправлять, только собрать текст
- `GOOGLE_SHEETS_ID` — таблица классифайдов (в примере уже указан публичный id)
- `GOOGLE_SHEETS_CLASSIFIEDS_GID` — лист, по умолчанию `0`
- `GOOGLE_SHEETS_PLANS_TAB` или `GOOGLE_SHEETS_PLANS_GID` — лист медиаплана, если он появится
- `GOOGLE_SHEETS_SYNC_HOURS` — период синхронизации, по умолчанию 3 часа
- `GOOGLE_SHEETS_API_KEY` или `GOOGLE_SERVICE_ACCOUNT_JSON` — если CSV по ссылке недоступен

Цели Метрики по-прежнему можно положить в `data/metrika-goals.json` (`node scripts/fetch-metrika-goals.js`).

## Планы подрядчиков

Источник — сводный отчёт за год, отдельная таблица: `GOOGLE_SHEETS_PLANS_ID` и `GOOGLE_SHEETS_PLANS_GID`. Чтение в ту же синхронизацию, что и классифайды, с тем же периодом `GOOGLE_SHEETS_SYNC_HOURS` и той же кнопкой «Обновить сейчас». В таблицу ничего не пишется.

Из отчёта берутся только два плана:

- **РЛ** — результативные лиды, штуки на месяц. В листе это колонка «План РЛ»: целые числа, рядом «Факт РЛ» и «РЛ LY». В дашборде это качественные лиды Calltouch, не все звонки и не расход.
- **CPL** — колонка «План CPL ОП», рубли за один такой лид. «ОП» в названии — отдел продаж; та же колонка стоит и в блоке сервиса.

Вкладка — один месяц, не год колонками. Месяц берётся из даты внизу листа (`01.11.2026`). Блок SALES — линия NC, блок AFTERSALES — AFS. «Марка» — бренд, «Агентство» — подрядчик («Тандем» записывается как Tandem). Строки EXEED и Esteo (Эксид, Эстео) складываются в один план «Exeed + Esteo»: РЛ суммируется, CPL — среднее, взвешенное по плану РЛ. Бюджет, показы, клики, CTR, CPC и все столбцы «факт» не импортируются.

Если `export?format=csv` отвечает 401, дашборд читает тот же лист через адрес gviz. Образцы формы с выдуманными цифрами: `data/samples/plans-summary.csv` (как живой лист) и `data/samples/plans.csv` (месяцы в колонках). Живые строки в git не входят.

На «Брендах» рядом с планом РЛ показан прогноз на конец месяца, если темп выбранного окна сохранится. CPL сравнивается с фактом окна: расход Директа / результативные лиды. Если прогноз РЛ отстаёт от плана на 20% (critical с 35%) или CPL выше плана на 25% (critical с 45%), это алерт. Пороги правятся в «Подключении», ноль выключает проверку. Окно короче 7 дней и меньше 8 лидов не экстраполируются. Алерт уходит в общий список и в Telegram.

## Классифайды

Отдельный экран. План и факт здесь те, что подрядчик сам вписал в таблицу, а не цифры Директа.

Лист «Текущий месяц» читается по публичной ссылке. В ячейке A1 месяц (`11.2026`). Дальше строка заголовков, важны названия, а не номер колонки:

- «План-факт» — проект
- «План расход» и «Факт расход»
- «План лиды» и «Факт лиды»
- «Прогноз расход», «Прогноз по лидам», «Run-rate», «CPL план», «CPL факт»

Правее в том же листе лежит прогноз расхода по auto.ru и avito и блок кошельков. Их заголовки тоже ищутся по тексту.

Простой файл для ручной загрузки, если это не тот лист: `month`, `contractor`, `brand`, `platform`, `metric`, `plan`, `fact`. Образец формы листа — `data/samples/classifieds.csv`, цифры в нём выдуманы. Живые строки таблицы в репозиторий не кладутся.

Синхронизация односторонняя, из таблицы в дашборд, каждые 3 часа (меняется `GOOGLE_SHEETS_SYNC_HOURS`). Кнопка «Обновить сейчас» на экране классифайдов и в «Подключении». Ручная загрузка файла при этом остаётся. Время последней синхронизации и текст ошибки видны там же.

Если CSV по ссылке перестанет открываться, нужен доступ «всем, у кого есть ссылка» или сервисный аккаунт с правом только на чтение.

## Обновление поверх уже стоящей папки

Не затирайте `.env`, `.env.local` и каталог `data`: там токены, настройки, цели Метрики, кэш и загруженные планы.

`data/samples/` при обновлении нужно скопировать отдельно.

```powershell
robocopy $env:TEMP\borishof-new C:\path\to\dashboard /E /XD node_modules .next .git data
robocopy $env:TEMP\borishof-new\data\samples C:\path\to\dashboard\data\samples /E
```
